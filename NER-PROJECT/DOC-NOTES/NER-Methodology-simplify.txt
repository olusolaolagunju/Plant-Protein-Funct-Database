Part 2 (Triple extraction): the core extraction prompt. Input is each chunk. Output is raw triples: source, source_type, interaction, target, target_type, pmid, section, chunk_text.
Part 3 (Experimental condition extraction): a second, separate prompt. Input is the chunk text plus the triples already extracted in Part 2. Output is one experimental_condition string per triple. Part 4 (Provenance capture): extracting corresponding_sentence for each triple. Your doc actually says this one should ideally ride along inside the Part 2 or Part 3 prompt output rather than be its own pass, to save cost, so this is the one phase that can collapse into another step rather than standing alone.
Part 5 (Entity resolution): a completely different kind of step. It doesn't touch the LLM extraction prompts at all. It runs after all triples exist, and does embeddings plus k-means clustering plus an LLM merge decision, scoped per entity type, to collapse duplicate entity names (e.g. "isoelectric precipitation" vs "isoelectric point precipitation").
