PART 2: TRIPLICATE EXTRACTION — WORK LOG
==========================================
Folder: PART-2-TRIPLICATE_EXTRACTION
Purpose: Phase 2 of the NER project — extracting structured (source, interaction,
target) triples from chunked plant-protein research paper text using LLMs, then
comparing models on cost/accuracy to pick a production model for the full corpus.

Upstream input (shared across all scripts):
- chunks_all.parquet
  Location: ../PDF_PREPROCESSING_INTO_CHUNKS/chunks_all.parquet
  This is the Phase 1 output (not in this folder) — chunked text from plant
  protein research papers, one row per chunk, with columns including doi,
  section, chunk_text.

Chronological work log (by file modification date)
----------------------------------------------------

1. Aug 3 — Triple Extraction Prompt.txt
   - Objective: first draft of the Phase 2 system prompt — defines the closed
     vocabularies (source_type, target_type, interaction) and extraction rules
     1-6 (negation guard, hedging/citation guard, compound method handling,
     multi-condition splitting, material-vs-source separation, comparative
     triples), plus 7 few-shot examples.
   - Input: none (hand-authored prompt spec).
   - Output: none (this file IS the artifact — the prompt used by the pilot
     run scripts below).

2. Aug 3 — sampled_30_chunks.csv (in model_comparison_output/)
   - Objective: fixed 30-chunk sample drawn from chunks_all.parquet (seed 42,
     chunks with >200 chars of text) reused across every pilot script so all
     models are compared on the exact same input.
   - Input: chunks_all.parquet.
   - Output: sampled_30_chunks.csv.

3. Aug 3-4 — multi-model_comparison_run.ipynb
   - Objective: pilot run comparing 5 candidate models on the same 30-chunk
     sample, to compare cost and extraction quality before committing to one
     model for the full ~1000+ chunk corpus. Models: gpt-5.6-terra,
     gpt-5.6-luna, gpt-5.5-pro (OpenAI), gemini-3.1-pro-preview,
     gemini-3.6-flash (Gemini).
   - Input: sampled_30_chunks.csv, Triple Extraction Prompt.txt / prompt text,
     OPENAI_API_KEY + GEMINI_API_KEY (.env).
   - Output: model_comparison_output/phase2_model_comparison_raw.xlsx,
     phase2_model_comparison_summary.xlsx.

4. Aug 4 — Openai.ipynb
   - Objective: split-out, OpenAI-only version of the pilot run (gpt-5.6-terra,
     gpt-5.6-luna, gpt-5.5-pro), with model-specific handling — terra/luna
     reject temperature=0, gpt-5.5-pro routed through /v1/responses instead of
     /v1/chat/completions.
   - Input: sampled_30_chunks.csv, phase2_extraction_prompt.md, OPENAI_API_KEY.
   - Output: model_comparison_output/phase2_openai_raw.xlsx,
     phase2_openai_triples.xlsx, phase2_openai_summary.xlsx.

5. Aug 4 — Gemini.ipynb
   - Objective: split-out, Gemini-only version of the pilot run
     (gemini-3.1-pro-preview, gemini-3.6-flash), with retry/backoff handling
     for transient 503 "model overloaded" errors seen on gemini-3.1-pro-preview.
   - Input: sampled_30_chunks.csv, phase2_extraction_prompt.md, GEMINI_API_KEY.
   - Output: model_comparison_output/phase2_gemini_raw.xlsx,
     phase2_gemini_triples.xlsx, phase2_gemini_summary.xlsx.

6. Aug 4 — Mergw_OpenAI_Gemini.ipynb
   - Objective: merge the OpenAI and Gemini pilot outputs into one combined
     table for side-by-side review across all 5 models, plus a combined
     summary sheet (cost/latency/failure stats).
   - Input: phase2_gemini_triples.xlsx, phase2_openai_triples.xlsx,
     phase2_gemini_summary.xlsx, phase2_openai_summary.xlsx.
   - Output: model_comparison_output/phase2_all_models_triples.xlsx,
     phase2_all_models_summary.xlsx.

7. Aug 4 — Models-triple-summary.txt
   - Objective: raw dump of every model's raw JSON output from the comparison
     run (one row per model + raw_output), used as source material for the
     manual error review below.
   - Input: pilot run raw outputs.
   - Output: this file (review artifact, not consumed by later scripts).

8. Aug 4 — errors from Luna.txt / errors identified.txt
   - Objective: manual, annotated error review of the pilot extraction output
     — logging concrete bad/ambiguous triples (unresolved sample codes like
     "UF", "G5-IP"; parameter-value comparisons wrongly tagged as
     outperformed/underperformed; recovery-rate/bookkeeping sentences wrongly
     extracted as triples). This review directly drove the prompt rewrite in
     phase2_extraction_prompt.md (rules 3-6 below trace back to specific
     numbered errors here).
   - Input: Models-triple-summary.txt / pilot triples output.
   - Output: these two text files (near-duplicate error logs).

9. Aug 5 — Luna.ipynb, first run — full-corpus extraction
   - Objective: after the pilot comparison, gpt-5.6-luna was selected as the
     production model (cheapest OpenAI-tier option, lowest citation-chain
     noise; gpt-5.5-pro's ~150-1300x cost premium wasn't justified by the
     quality gain). Runs the extraction prompt against every chunk in
     chunks_all.parquet (not a sample), with checkpointing every 25 chunks,
     auto-resume, and retry/backoff for transient errors.
   - Input: chunks_all.parquet (full), phase2_extraction_prompt.md,
     OPENAI_API_KEY.
   - Output: LUNA/phase2_luna_full_checkpoint.jsonl,
     LUNA/phase2_luna_full_raw.xlsx, LUNA/phase2_luna_full_triples.xlsx.

10. Aug 6 — resolve_sample_codes.py, first pass
    - Objective: pure post-processing (no further API calls) on Luna's full
      output — flags rows where source/material/target is still a bare local
      sample code (e.g. "TT", "SS", "PA", "PPI 1", "HP-20") despite the
      prompt's code-resolution rule, cross-references other rows from the
      same chunk to find what the code stands for, and writes both a
      reviewable "best-guess + confidence" file and a corrected triples copy.
    - Input: model_comparison_output/phase2_luna_full_triples.xlsx (copy of
      the LUNA/ output).
    - Output: model_comparison_output/phase2_luna_full_triples_code_review.xlsx,
      phase2_luna_full_triples_fixed.xlsx.

11. Aug 6-7 — Terra.ipynb — full-corpus extraction (second candidate)
    - Objective: same full-corpus pipeline as Luna.ipynb, swapped to
      gpt-5.6-terra, run as a second full-corpus candidate for direct
      cost/quality comparison against Luna at full scale (not just the
      30-chunk pilot).
    - Input: chunks_all.parquet (full), phase2_extraction_prompt.md,
      OPENAI_API_KEY.
    - Output: model_comparison_output/phase2_terra_full_checkpoint.jsonl,
      phase2_terra_full_raw.xlsx (Aug 6), phase2_terra_full_triples.xlsx
      (Aug 7).

12. Aug 7 — Sonnet.ipynb — full-corpus extraction (third candidate) + fix test
    - Objective: same full-corpus pipeline again, swapped to claude-sonnet-5
      via the Anthropic API (client.messages.create instead of OpenAI's
      client.chat.completions.create), run as a rigorous, reproducible
      third comparison point against Luna/Terra — explicitly to replace an
      earlier ad hoc chat-based comparison that lacked fixed system/user
      separation, temperature control, and had context bleed between chunks.
      Includes a small-scale validation cell that reruns only the 2 articles
      whose chunks were failing with a NO_TEXT_BLOCK error, to confirm the
      fix before re-running the full 1104-chunk job.
    - Input: chunks_all.parquet (full, and a 2-DOI subset for the fix test),
      phase2_extraction_prompt.md, ANTHROPIC_API_KEY.
    - Output: model_comparison_output/phase2_sonnet_full_checkpoint.jsonl,
      phase2_sonnet_full_raw.xlsx, phase2_sonnet_full_triples.xlsx,
      sonnet_small_test_results.xlsx (fix-validation run).

13. Aug 7-8 — Manual error review of Sonnet and Luna
    - Objective: hand review of extraction quality on the two full-corpus
      candidates, archived for reference.
    - Input: phase2_sonnet_full_triples.xlsx, phase2_luna_full_triples.xlsx.
    - Output: model_comparison_output/Other-models-output/Sonnet-errors.xlsx
      (Aug 7), Other-models-output/luna-errors.xlsx (Aug 8).

14. Aug 10 — model_comparison_output/ reorganized
    - Objective: older pilot/comparison artifacts and per-model error sheets
      archived into an Other-models-output/ subfolder to separate them from
      the active production outputs.

15. Aug 12 — resolve_sample_codes.py / resolve_comparison_codes.py, final pass
    - Objective: resolve_sample_codes.py re-run/finalized as the general
      bare-code resolver described in step 10. resolve_comparison_codes.py
      added as a narrower companion: scans only comparison-type rows
      (interaction = outperformed / underperformed / equivalent_to), since
      those need two cleanly resolved entity names to be useful for
      knowledge-graph merging; substitutes a fuller name found elsewhere in
      the same chunk, or leaves the row flagged "unresolved" for manual
      review rather than guessing.
    - Input: full-corpus triples tables (Luna/Terra/Sonnet).
    - Output: updated *_code_review.xlsx / *_fixed.xlsx files, per model.

16. Aug 12 — Luna.ipynb / Sonnet.ipynb / Terra.ipynb, rebuild passes
    - Objective: "Rebuild"/"rebuild output file" cells added to regenerate
      each model's final output files after the code-resolution fixes above,
      refreshing the triples tables without re-running the underlying API
      calls from scratch.

17. Aug 12 — phase2_extraction_prompt.md finalized
    - Objective: mature, production version of the Phase 2 prompt, rewritten
      from Triple Extraction Prompt.txt directly in response to the errors
      logged in step 8. Adds: rule 2 now skips (not just tags) cited/hedged
      sentences entirely, to cut cost and noise; rule 3, mandatory local
      sample-code resolution with a new `raw_code` field (feeds the resolver
      scripts above); rule 4, parameter values (ratio/pH/concentration) may
      never populate source/target; rule 5, a treated-vs-untreated baseline
      is not an entity comparison; rule 6, excludes definitional/
      classification/bookkeeping statements (e.g. recovery-rate figures used
      only to justify a naming choice). This is the prompt actually used by
      Luna.ipynb, Terra.ipynb, and Sonnet.ipynb's full-corpus runs.

Supporting files
-----------------
- .env — holds OPENAI_API_KEY, GEMINI_API_KEY, ANTHROPIC_API_KEY used by every
  script above. Not committed/shared; contains live secrets.
- LUNA/ — full-corpus output of the production Luna run (checkpoint, raw,
  triples).
- model_comparison_output/ — all pilot-comparison and full-corpus outputs for
  Terra and Sonnet, plus the two code-resolution scripts and the
  Other-models-output/ archive of older/error-review files.

Output file naming convention (applies across Luna/Terra/Sonnet/pilot runs)
------------------------------------------------------------------------------
- *_raw.xlsx            one row per (model, chunk), raw LLM JSON response
- *_triples.xlsx         flattened, one row per extracted triple
- *_checkpoint.jsonl     resumable progress state for long unattended runs
- *_summary.xlsx         per-model cost/latency/failure stats
- *_code_review.xlsx     bare local sample codes flagged + best-guess resolution
- *_fixed.xlsx           triples table with confident code resolutions applied
- *-errors.xlsx          manual/hand-reviewed error sheets
